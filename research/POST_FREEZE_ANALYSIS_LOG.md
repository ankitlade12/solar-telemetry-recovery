The frozen protocol specified the estimands, scoring population, matched contrasts, seven-day common-calendar blocks, 14/28-day checks, 10,000 bootstrap replicates, base seed and exploratory sensitivity scope. The separate analysis program implements those choices. Each site/population/pool/endpoint/contrast/block combination derives a stable seed by adding the first 32 SHA-256 bits of its ordered key to the frozen base seed modulo 2^32. This avoids dependence on the order in which a table is generated.

A bootstrap replicate can contain no eligible observations for an otherwise supported case/horizon stratum. Such replicates are rejected, rather than silently averaging over a different subset of strata. The output reports valid replicate count and rejection fraction. The point estimate retains the original supported strata. This is an implementation detail fixed before inspecting final effects, and large rejection rates must be treated as an uncertainty limitation.

Direct score verification uses the sum of seven pinball losses, independently of the interval-score implementation. Delivery verification looks up visible slots directly from delivered packets and separately counts receipt-gated updates and pending forecasts from issued target ends. These automated checks do not claim a second human contributor's reproduction.

Diagnostics retain insufficient-score and absent-matching-state fallback rates separately. Update activity counts scored forecast records over all horizons, not unique physical labels, and deduplicates the diagnostic that is repeated in every horizon row. It reports mean, maximum, 95th percentile and fraction of origins with updates. This descriptive diagnostic is not an additional selected significance test.
